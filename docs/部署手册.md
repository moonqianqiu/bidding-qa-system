# 部署手册

> 适用：本机开发/单机部署（Windows，绿色安装路线）。容器编排为可选演进，不在本期。
> 本文是**运维唯一入口**：安装/启停/数据初始化/验收命令/运维日历/排障坑表都在这里。

## 1. 首次安装

```bash
# 1) 依赖：Python 3.14 + Node 22 + uv
# 2) 绿色数据服务（zip 落 services/，数据在 data/db/，删目录=彻底卸载）
bash deploy/download-services.sh     # 分段并行下载（走 PDL_PROXY 可选）
bash deploy/install-services.sh      # 幂等解压 + initdb + Neo4j 初始密码 bidqa_dev_2026

# 3) 后端
cd backend
uv sync
cp .env.example .env                 # 填三槽位（CHAT_*/EMBEDDING_*/JUDGE_*）见 docs/01 §5

# 4) 前端
cd ../frontend && npm install
```

## 2. 启停与状态

```bash
bash deploy/start.sh    # PostgreSQL → Qdrant → Neo4j → backend(uvicorn workers=1，写死)
bash deploy/status.sh   # 端口+pid属主+HTTP 表；「存活但未持有」=陈旧记录（旧代码还在跑的信号）
bash deploy/stop.sh     # 逆序停机（属主校验后杀）+ 残留检测
```

- **workers=1 是硬性约定**（限流/在线评测/日志缓冲/压缩缓存均进程内状态）。
- **pid 文件 = 真实监听者的 Windows pid**（start.sh 由 `netstat -ano` 端口归属取得）。
  stop 前做属主校验：pid 必须仍持有对应端口才杀，陈旧记录拒杀不误杀；存活检测走 `ps -W`（无特权），
  taskkill 被环境拦截时 PowerShell `Stop-Process` 兜底。
- PG 需 `SeCreateGlobalPrivilege`（本项目已一次性授权；重装系统后重跑
  `deploy/grant-createglobal.ps1`）；管理员账户下由 start.sh 预置 `PG_RESTRICT_EXEC=1` 跳过自降权。
- Neo4j 必须配微软 JDK21（`services/jdk21`，start.sh 自动探测）。
- 端口：后端 8000 / 前端 dev 3000 / PG 5432 / Qdrant 6333 / Neo4j 7474+7687。

## 3. 数据初始化

```bash
cd backend
uv run bidqa ingest knowledge --input <FAQ.xlsx>            # 知识库（嵌入+双稀疏）
uv run bidqa ingest db --input <业务.xlsx> --sheet Sheet2    # 业务库（金额/地区归一）
uv run bidqa ingest graph --batch-id sample --clear          # 图谱（约束先行）
uv run bidqa ingest pdf --input <法规.pdf> --source-type 法规 --title <标题>   # PDF/法规/招标文件（F2/F3/F4，先加 --dry-run 预览）
uv run bidqa doctor                                          # 体检：配置/连通/槽位/source_type 分布
uv run bidqa user add <名> --role user [--password]           # 建号（缺省交互输口令；首次调用自动建表+种子管理员）
uv run bidqa user reset <名> [--password]                     # 重置口令（admin/admin123 默认口令改密用这条；改密即吊销该用户全部会话）
uv run bidqa user disable <名>                                # 停用（其会话即刻失效）；enable 反之
uv run bidqa user list                                        # 列出用户
```

> **用户管理 / 游客开关 / 全库会话清理已有 GUI**（2026-11-09）：admin 登录 → 侧栏「▦ 控制台」（`/console`），
> 建号/改密/停用、游客开关、空壳会话清理由界面完成；上表 CLI 保留作脚本通道（语义同款：改密同事务吊销会话、开关即时生效）。

**标的物批量提取**（F6 数据修复：PG 8,489 行 subject_matter 全 NULL → 免费档 GLM-4.7-Flash 同步并发回填）：

```bash
uv run bidqa subject-batch build   # 拉去重项目名 → requests.jsonl + names.json（--dry-run 只打印）
uv run bidqa subject-batch run     # 同步并发执行（需 .env 配 SUBJECT_BATCH_API_KEY；断点续跑，--workers 调并发）
uv run bidqa subject-batch fetch   # 解析 → subject_map.json（默认试运行；--write 才写回 PG）
```

国际版 z.ai 无 Batch API（openapi.json 核实），故为同步并发直调 chat/completions；
结果行增量落盘可断点续跑，失败条目已记行（重跑 run 跳过已落盘项，要重试失败项先删对应行）。
统一试运行约定：以上命令均支持 `--dry-run`（打印条数+抽样5条+不写库）。

## 4. 验收命令（改代码后全跑一遍）

```bash
cd backend && uv run pytest -q                                      # 全量全绿（服务离线时集成例 skip 属预期；计数以实跑为准）
cd frontend && npx tsc --noEmit                                     # 类型
bash deploy/e2e-chat.sh                                             # SSE 三走向（机器断言；真实调用主模型；先自动登录——ADMIN_* 读 backend/.env，缺省 admin/admin123，失败回落机器主 token）
bash deploy/e2e-chat.sh --mutation-check                            # 断言器自证：坏流必须 FAIL（无需后端）
uv run bidqa eval --golden ../eval/golden/rag_v0.jsonl --mode smoke     # 引用可定位 100%
uv run bidqa eval --golden ../eval/golden/agent_v0.jsonl --mode agent   # 工具选择 ≥90% / hit_cap <10%
uv run bidqa prune --days 30 --dry-run                              # 数据保留（先预览再真删）
uv run bidqa ingest pdf --input <法规.pdf> --source-type 法规 --title <标题> --dry-run   # PDF 链路试运行（不写库/不调模型）
bash .auto/measure.sh                                               # 文档机械审计（doc_defects 应为 0）
```

## 5. 运维日历与数据资产

**节奏**：
- 每次开机：`bash deploy/start.sh` + 前端 `npm run dev`
- 改了语料/数据：重新 ingest → **必查检索三路**（`eval smoke`，hit_rate 应 1.0）；`ctx_summary` 空摘要合法入库（F3 诚实降级），查库里 source_type 覆盖度用 `uv run bidqa doctor`（取不到记「不可用」）
- 每周（决策 #8）：人工巡检 SiliconFlow/SenseNova/判分中转控制台额度（>60% 冻结批量操作）；
  `prune --days 30 --dry-run` 看看数据量
- 发版前：DoD 清单（docs/03 §0.1）→ pytest/tsc/e2e/eval 全绿 → 打 tag

**数据在哪**：

| 资产 | 位置 | 说明 |
|---|---|---|
| 库文件 | `data/db/`（PG/Qdrant/Neo4j） | gitignore，别手动动 |
| 日志/pid | `data/run/` | 排障第一现场 |
| 评测快照 | `backend/eval/results/*.json` | 命名含日期+git hash，滚动保留 100 |
| 判分缓存 | `backend/eval/results/judge_cache/` | 按端点-模型分目录 |
| 会话数据 | PG `conversations` 表 + 浏览器 localStorage | 双写，前端删会话两边都删 |

**前端用户设置（localStorage）**：`bidqa.theme`（dark/light/system）· `bidqa.lang`（zh/en）·
`bidqa.provider`（模型档位）· `bidqa.conversations.v1`（本地会话）。

**回滚演练**：v1.0 前已完成两项（.env 注入 + 版本回滚，均通过），记录见 [开发日志](./开发日志.md)。

## 6. 排障坑表（症状 → 动作，按踩坑次数排序）

### 服务与部署

| 症状 | 处置 |
|---|---|
| PG/服务成批 `0xC0000142 STATUS_DLL_INIT_FAILED` | 沙盒会话进程树被系统加固拦截：**让用户在自己终端跑 `deploy/start.sh`**，或命令加 `dangerouslyDisableSandbox` |
| PG initdb 报 1314 | 授 SeCreateGlobalPrivilege（`deploy/grant-createglobal.ps1`，重登生效）+ `PG_RESTRICT_EXEC=1` |
| Neo4j 启动报 `UnsatisfiedLinkError: jnidispatch.dll ... 拒绝访问` / `AccessDeniedException: D:\Temp\UserTemp\decompressed-browser*` | 全局临时目录多会话共用，JNA 与 browser 解压遇残留/属主不匹配被拒；`start.sh` 已给 JVM 独立 `-Djava.io.tmpdir` + `-Djna.tmpdir`（2026-11-10 实证修复） |
| Neo4j 起来但不应答 | `deploy/nio-test.cmd`：SELECTOR-DEAF = 系统加固拦截 WEPoll（非项目问题） |
| health 图谱「不可用」但 Neo4j 进程在跑 | 先查端口错位：`netstat -ano \| grep 7687`。`services/neo4j/conf/neo4j.conf` 尾部的定制段若写 7475/7688 会与约定端口（.env/手册/start.sh/config 默认）错位，后端永远连不上（2026-11-08 实证已修回 7474+7687）；次查 `data/run/neo4j.log` 的 `Bolt enabled on` 行确认实际监听口 |
| hosts 有 Typora 条目 | `deploy/fix-hosts-localhost.ps1`（127.0.0.1 localhost 置首） |
| 改了代码没生效、答案还是旧语义 | 已根治（2026-11-07）：pid 文件记真实监听者 + stop 属主校验 + status「存活但未持有」会点名。历史坑：pid 曾记 `uv` 包装进程，真服务是 python 子进程，按 pid 杀不掉 |
| 后端探活 000/拒绝 | `bash deploy/status.sh`；`tail data/run/backend.log` 看日志末尾 |
| status 显示「已死(残留)」 | 残留 pid 文件不是故障，start 前不用手动清 |
| tasklist/taskkill 报「用户名或密码不正确」 | 受控/沙箱会话的系统加固拦截（非项目故障）：启停脚本已内置对策——存活检测走 `ps -W`、停止 taskkill→PowerShell `Stop-Process` 兜底；彻底不行就让用户终端跑 |

### 后端行为

| 症状 | 处置 |
|---|---|
| health `status:degraded` | `/api/health` 的 components 看哪个「不可用」；按槽位查 key/网络。设计就是单点降级不断服 |
| 回答总是「未包含」/ 命中率 0 | dense/sparse 两路是否齐全（dense 缺失坑）→ `eval smoke` 看 hit_rate；低就真实 key 重新 `ingest knowledge`（入库后必查检索 mode 的教训见开发日志 11-02） |
| 来源相关度条消失 / CRAG 每次都改写 | 未配 `RERANK_*` 时 `sources[].score` 为 `null`（RRF 排名分不冒充相关度）属预期：前端不显示相关度条、`quality_note` 不贴标签、CRAG 不触发改写。若配了重排仍无条，查重排分是否为有限数 |
| 上游 429 `inference exceeds tpm/rpm limit` | sensenova 自动退避（≤45s 总预算）；长时间连续 e2e 仍可能耗尽 → 降并发/等额度。**其它端点 429 原样报错，勿加全局重试**（红线见 AGENTS.md） |
| 空白气泡 | 已双层自动处理（2026-11-10）：①llm 空流（200 但 0 chunk）在自建中转端点补发一次；②loop 最终空正文补发一次无工具直答——仍空才下发 `empty_answer` 诚实文案（补发成功记 `empty_answer_retry`，降级面板可见）。排查查 `backend.log` 的「上游流式响应为空」；若诚实文案仍频繁出现，说明上游故障持续，考虑换端点/模型 |
| 多轮工具调用 HTTP 400 `invalid arguments` | 回传 assistant 的 `function.arguments` 必须是 JSON **字符串**（`loop.py`，勿回退） |
| 工具反复报 bad_arguments | 模型传参 vs 工具枚举/白名单。正常现象：工具回错误→模型自纠（看 degraded 记录）；频繁出现就锐化工具描述 |

### 前端

| 症状 | 处置 |
|---|---|
| token 全部最后一次性到达 | 是否走了 Next 代理——`lib/sse.ts` 必须直连 `127.0.0.1:8000`（代理会缓冲整个 SSE） |
| 前端白屏 / hydration 卡死 | `next.config` 的 `allowedDevOrigins`（127.0.0.1 被判跨域拦 hmr）；`127.0.0.1:3000` 不通时用 `localhost:3000` |

### 命令行与工具链

| 症状 | 处置 |
|---|---|
| `uv run` 报 exe 占用 / lock 拒绝访问 | 有进程持着 venv：先停后端再跑，或加 `--no-sync`；沙盒拦 uv 缓存锁时关沙盒执行 |
| `uv trampoline failed to canonicalize script path` | venv 入口 exe 烧录的是**创建时的绝对路径**——仓库改名/移动后失效。普通 `uv run`（不带 `--no-sync`）触发 sync 即自愈项目自身入口；第三方入口（如 pytest）需 `uv sync --reinstall-package pytest`；彻底重置：删 `backend/.venv` 后 `uv sync` |
| curl 中文 body 400/乱码 | 终端传参坏编码 → 写 UTF-8 临时文件 + `--data-binary @file`（e2e 脚本即此法） |
| `bsk daemon` 起不来 `os error 10048` | 旧守护进程占 52800 但 `daemon.json` 指向死管道：等旧进程退 → `daemon start --foreground` |
| backend/ 下出现 jieba.cache / pytest-of-* / tmp* 产物 | 环境缺 TEMP 时 tempfile 兜底到当前目录；conftest 已把临时根钉到系统目录、.gitignore 有兜底规则——若仍出现，设置 TEMP/TMP 后重跑 |
| 跑完 pytest 图谱变空 / PG 冒出 3 行 it-* 数据 | 已根治（2026-11-08）：`test_graph` 模块夹具曾 teardown `clear_all()` **清空真实图谱**、`test_subject_writeback` 收尾不清理留 it-sm 残留（+3 行之谜）；已改前缀 scoped 清理（图谱只删 IT-G* 自建节点、PG it-sm try/finally）——跑完测试 PG/图谱计数不变。历史事故重建：`uv run bidqa ingest graph --batch-id sample --clear`（约 20 分钟，normalize 大包调用失败属诚实降级） |
| 重导入业务 xlsx 后 region 又现「江西省合肥市」类错值 | 源表省列自带 3 行错配，导入端省份+市区为裸拼接无校验（db_import.py 组合路径）。复修 SQL（条件更新防误伤）：`UPDATE bidding_procurement SET region='安徽省合肥市', updated_at=now() WHERE project_no IN ('2023AGGGZ00095','2023ANNBZ00440') AND region IN ('江西省合肥市','浙江省合肥市'); UPDATE bidding_procurement SET region='安徽省芜湖市', updated_at=now() WHERE project_no='WH21CG2023FW137201-1' AND region='江苏省芜湖市';` |
| 联网搜索按钮不出现 / 想开联网 | `.env` 的 `WEB_SEARCH_PROVIDERS` 留空=关（前端按钮隐藏）；填 `WEB_SEARCH_PROVIDERS=tavily` + `TAVILY_API_KEY`（exa 同理可并列：`tavily,exa`）后重启生效；配置 `RERANK_*` 后联网结果带相关度标注 |
| 打不开页面 / 全部请求 401 跳登录 | 用户体系默认开启（USERS_ENABLED=true）：登录 `admin/admin123`（首次启动自动种子）；改密 `uv run bidqa user reset admin --password <新口令>`；想退回免登录单机模式设 `USERS_ENABLED=false` 重启 |
| 想关游客入口 / 踢掉在线游客 | **控制台 →「游客入口」开关**（admin 登录 → /console，即时生效：既有游客会话下一请求即 403）；SQL 备选：`UPDATE app_settings SET value='false' WHERE key='guest_enabled'`；`'true'` 恢复 |
| 游客聊天第二轮「失忆」/ 重启后游客会话消失 | 游客会话**不落库**（docs/01 §3.1 游客语义）：多轮上下文走进程内缓存（TTL 1h 封顶 6 轮），**后端重启即清空**——属设计语义不是 bug；游客刷新页面历史同样消失 |
| 普通用户看不到/删不了别人的会话 | 会话隔离（conversations.user_id）：普通用户仅本人；机器主 token 与人类 admin 可见 NULL 机器域（存量历史会话都在机器域，用 admin 登录可见）；越权一律 404 属设计 |
| Helium 无头截图出不了文件（exit 0） | 用 `bsk` 走真实浏览器，别用 `--headless` |

### 评测

| 症状 | 处置 |
|---|---|
| 评测分数离谱 | **先 `status.sh` + `/api/health` 再跑**——PG 静默宕机曾让 6 题被迫选错工具产出 0.54 假分数；评测有 precheck 门禁会拦，但先看更省时间 |
| 相关性 0 分（忠实度却 1.0） | 先看回答正文再怀疑判分：回答为「知识库未包含」类拒答时 0 分是**正确信号**（判分提示词即「拒答式空话=0」，`eval/ragas.py`）；陷阱是有实质内容却以「参考材料中未直接给出…」对冲式开头，可能被误读为回避而误判 0（参考项目同款经验）——实质作答的正常落点不是 0 |
| 判分跑批成本/时长没概念 | 口径：离线 rag 模式单题 3 次**二值**判分调用（三维各 1 次、温度 0、材料截 1500/回答截 1200 字符）× golden 8 题 ≈ 24 次小调用；agent 模式工具选择是行为指标、**0 判分调用**；判分缓存命中后同题重跑零成本；整批耗时大头在生成侧（每题真跑主模型） |
| 数据服务停机跑 pytest | 集成例 skip 属预期（PG/Qdrant/Neo4j 离线时 conftest 自动跳过），非故障 |
