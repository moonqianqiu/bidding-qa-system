## 1. 分层架构与模块总览

```
frontend/ (Next.js 16)                    ← 交互层
    │ HTTP + SSE（生产经 /api/* 代理，SSE 直连后端端口）
    ▼
backend/src/bidqa/
    api/        接口层   路由·鉴权·限流·校验·SSE协议·统一错误模型（chat/ 与 system/ 分包，端点=适配壳）
    application/ 用例层  非平凡业务编排（ask/image/{refs,qwen,ocr,analyze}/chat/{worker,history,degrade}/admin）——不 import FastAPI
    agent/      调度层   上下文构建·工具表组装(assembly)·工具循环·澄清闸门·生成·压缩·技能·prompts 收口
    tools/      工具层   6个取数工具 + ToolRunner（并行/超时/隔离）
    rag/        检索层   分类·编码(API)·混合召回·精排(API)·缓存·CRAG-lite + factory
    clients/    模型层   三槽位+OCR 通用适配器（llm）+ chat_factory/web_factory + 嵌入/重排客户端
    database/   数据层   PgConn 连接 + 三存储（bp_repo/conversations/feedback）+ bp_query 纯函数 + factory + 三库
    auth/       认证层   identity/passwords/store 三表访问 + factory
    ingest/     管道层   Excel/PDF解析·上下文增强切分·嵌入入库·图谱构建·业务库导入（+regions 词表）
    eval/       评测层   黄金集·离线RAGAS·Agent评测·在线评测·快照
    obs/        观测层   请求计数·内存日志环·脱敏（logs.py；Langfuse 未配静默）
    cli/        命令行   main 接线 + serve/doctor/prune/user/eval/ingest/subject-batch 七命令
    config.py   配置     .env 加载（override=False）+ 启动校验
    container.py 组合根  入口级整栈装配（build_agent_stack，评测/诊断用）——API 不经过
    errors.py   错误     错误码表 + error_body（纯契约；异常安装在 api/error_handlers.py）
```

> **模型面全 API 化（已确认决策）**：本地**无 GPU 且零模型**——嵌入、重排、文本生成、深度思考、
> 判分、视觉、PDF 解析**全部调用云端 API**。本地只跑 Python 服务与纯 CPU 无模型工具（pdfplumber 兜底解析）。
> - **三槽位自填**：主模型/视觉/判分各自一份 `{base_url, api_key, model}` 通用配置，同一 **OpenAI-compatible 适配器**覆盖——无预置厂商枚举，支持兼容端点的厂商即插即用；.env.example 附常用厂商示例注释。v2.3 增 OCR 槽位（能力型，同构自填）
> - **异源判分**：按「端点+凭据+模型」指纹校验——判分与主槽位指纹完全相同→拒绝跑批（5032）；仅端点相同→告警确认
> - 嵌入：SiliconFlow `BAAI/bge-m3`（稠密 1024 + 稀疏一次返回）+ **本地 jieba BM25 灾备通道**（ingest 双稀疏写入，API 不可用/断网时纯本地检索）；重排降级=跳过精排取 RRF 融合结果
> - 深度思考：主槽位可选子配置（该端点推理模型，reasoning_content 双流）；未配置/失败回退提示词注入
> - PDF 解析：MinerU 官方 API（云端）；本地 **vLLM/Ollama 均不实现**；Langfuse 观测延后（obs 未配置静默禁用）
> - **数据服务绿色安装**：Qdrant/PostgreSQL/Neo4j 官方 zip 落项目 `services/`，数据在 `data/db/`，启停脚本编排；Compose 降为可选路线

## 2. 模块职责矩阵

| 模块 | 负责 | **不**负责 | 关键约定（继承参考方案的已验证设计） |
|---|---|---|---|
| `api/` | 路由、参数校验、响应组装、限流、鉴权🆕、健康检查、**统一错误体**🆕——**HTTP 适配壳** | 业务逻辑（编排下沉 application） | 端点同步 `def`（线程池执行，慢请求不阻塞事件循环）；健康检查缓存 30s；settings 全部 Depends 注入（C4 收口直调） |
| `application/` | 非平凡业务用例编排（ask/image/chat/admin）；不 import FastAPI（可脱离 HTTP 单测） | HTTP 语义、纯转发（不建空壳——auth/conversations/users 薄直调） | 依赖单向：application→agent/rag/clients/database/auth；不得 import api/cli/container |
| `agent/` | 决定调哪个工具、多轮循环、澄清判定、技能注入、并行执行 | 具体取数 | 单工具挂掉返回失败文本不抛异常；澄清判定先于工具白名单过滤 |
| `agent/` 生成侧（loop/prompts/compress） | 最终生成、深度思考、上下文压缩、降级路径 | 工具选择 | 无工具的降级路径不支持澄清（没有工具表） |
| `tools/` | 工具定义、注册、ToolRunner 并行执行 | 数据源内部实现 | 一轮内并行；整批共享 30s 墙钟；未知工具/坏参数也返回 tool 消息 |
| `rag/` | 编码(API)、召回、融合、精排(API)、缓存、CRAG-lite重检🆕 | 生成答案 | 查询与文档**同一编码 API 入口**（否则分数不可比）；先扩召回再精排 |
| `clients/` | 三槽位（主模型/视觉/判分）+ OCR（v2.3 能力槽位）通用 OpenAI-compatible 适配器 + 嵌入/重排客户端 | 业务提示词 | 槽位=自填 {base_url,api_key,model}；LLM 统一 `chat/chat_stream/chat_stream_thinking/chat_raw`；嵌入/重排客户端带**批量、重试、限流退避** |
| `database/` | 三个库的连接池与查询模板 | SQL 之外的逻辑 | 字段/聚合函数白名单；参数化 SQL；LIKE 通配符转义 |
| `ingest/` | 全部离线数据管道 + **payload schema 校验与拒收**🆕 | 在线服务 | 每个脚本支持试运行模式；共享校验逻辑下沉、脚本不反向依赖服务 |
| `eval/` | 黄金集、离线/在线评测、快照 | 修复质量问题 | 快照原子写+命名规范🆕；判分与被测**异源（执行前强制校验）**🆕；终端数字与落盘数字同源 |
| `obs/` | 请求计数（note_request）、内存日志环、脱敏（logs.py） | 反向依赖 API（R2 钉死） | 未配置凭据即静默禁用；脱敏规则**先具体后通用**；单进程约定 |

**跨层硬约束**（写进 AGENTS.md 的改动须知）：
- 取不到的数值记「不可用」，绝不记 0；无数据整图不出
- 只缓存成功结果；缓存返回深拷贝
- 数值归一、历史边界计算、**金额归一**🆕各只有一个入口
- 后台任务用守护线程；队列容量即并发上限，满即丢不排队
- 包 `__init__.py` 保持为空（防重量级依赖拖进冷启动）

**分层守卫**：`backend/tests/test_layering.py` 用 AST 钉死 R1-R11——业务层不依赖 api/cli/container/service、
obs 不依赖 api、api 不依赖 cli/container/agent、api.system 不依赖 api.chat、application 不依赖 FastAPI、
database 不依赖 rag；每条规则带「能红」自检，allowlist 必须与实际违规双向一致（修好即删条目）。
v2.2 起 `errors.py` 为纯错误码/错误体契约，FastAPI 异常处理器在 `api/error_handlers.py`。

## 3. 接口契约

### 3.1 HTTP 端点

| 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|
| GET | `/api/health` | 各数据源连通性+就绪状态 | 缓存 30s；失败耗时记「不可用」；**免鉴权** |
| POST | `/api/auth/login` | 账号密码登录 → `{token, username, role}` | 凭据错误统一 401/4011（不区分「用户不存在」，防枚举）；**免鉴权**（登录引导） |
| POST | `/api/auth/guest` | 游客进入 → `{token, username:"guest", role:"guest"}` | `app_settings.guest_enabled` 运行时开关关闭 → 403/4031；游客无 users 行（user_id=NULL） |
| GET | `/api/auth/me` | 当前身份 → `{authenticated, users_enabled, guest_enabled[, username, role]}` | 未登录 200（登录页渲染依据，不产生 401 噪音）；**免鉴权** |
| POST | `/api/auth/logout` | 注销当前会话 | 机器主 token 无会话可删，幂等返回 |
| POST | `/api/ask` | 直连知识库问答（非流式） | **长期保留**：降级路径 + 评测 smoke 直连，不标 deprecated |
| POST | `/api/chat/stream` | Agent 问答（SSE 流式，主端点） | 限流 30次/60s（游客 10次/60s 独立桶）；**需鉴权**；schema 见 §3.3 |
| POST | `/api/vision` | 图片解析 → 返回 `image_ref` | 请求 `{image(压缩预览), original?(高分辨率原件), mode?(auto/ocr/describe,默认auto), filename?}`；响应追加 `mode_used`("describe"/"ocr")、`route_by`("auto"/"manual"/"unavailable")、`degraded`。**v2.3 双通道**：mode=auto 由 Qwen 看预览路由（文档类→OCR 读原件；OCR 未配置=退化通用描述）；mode=ocr 手动按文档解析（跳过 Qwen 最省钱，需 OCR 槽位+原件）；mode=describe 强制通用描述。体积超限 413/4131（base64 > 4M 字符/字段）；解码失败/mode 非法/mode=ocr 缺原件 400/4001；VISION 未配置（所有 mode）或 mode=ocr 且 OCR 未配置 5031；**仅解析不检索**；聊天只传引用不传 base64；需鉴权；**游客 403/4031** |
| GET/PATCH/DELETE | `/api/conversations[/id]` | 会话 CRUD / 重命名 / 清空 | 标识符非法一律 404/4041；PATCH 标题非空 ≤100 字；**按查看者过滤可见域**（见下「会话隔离」）；游客 403/4031 |
| POST | `/api/feedback` | 反馈落库（可带回传来源） | 点踩触发必评；需鉴权（游客可评，匿名信号） |
| GET | `/api/eval/runs[/{id}]` `/api/eval/live` | 评测快照与实时统计 | `EVAL_ENABLED=false` 时整体 404；需鉴权 |
| GET | `/api/system/metrics` `/api/system/logs` | 资源与内存日志 | **仅管理员**（403/4031）；`/api/system/providers` 全员可达（档位下拉用） |
| GET | `/api/system/console` | 三库规模聚合（KPI 仪表盘） | **仅管理员**；30s 缓存；`pg{bidding_procurement, conversations, feedback, users}` + `qdrant{vectors, collection}` + `neo4j{labels 六类, total}`；任一库挂 → 该节 `{"status":"不可用"}` 绝不记 0，其余节照常 |
| GET/POST | `/api/system/users[/name/reset-password\|disable\|enable]` | 用户管理（列表含活跃会话数 / 建号 / 改密吊销会话 / 停用·启用） | **仅管理员**；重名建号 409/4091；密码 ≥4 位（4001）；改密同事务吊销该用户全部会话（CLI `user reset` 同款）；停用自己 400/4001 |
| POST | `/api/system/settings/guest-enabled` | 游客开关 | **仅管理员**；`{enabled: bool}`；即时生效（中间件逐请求复核，在线游客一并 403） |
| GET/DELETE | `/api/system/conversations[/id]` | 全库会话列表（属主 JOIN + 标题 ILIKE 过滤）/ admin 旁路删 | **仅管理员**；**独立旁路端点**——聊天页可见域三元组零改动；不存在/非法 id 404/4041 |
| POST | `/api/system/conversations/purge-empty` | 空壳会话清理 | **仅管理员**；`{dry_run}` 缺省 true=只预览 `{count, samples≤20}`；判定=无 assistant 回复且 `updated_at` 超出 10 分钟保护窗（防误删刚流式完成的活跃会话）；false 才删 → `{deleted}` |

**鉴权（用户体系，2026-11-08）**：三角色 `admin / user / guest`。`API_AUTH_TOKEN` =
**机器主 token**（脚本/e2e 免登录，语义=管理员级，不经过用户体系）；人类经
`/api/auth/login`（或游客入口）取 opaque 会话令牌（sessions 表，TTL `SESSION_TTL_HOURS`
默认 72h，可吊销），此后全部请求带 `Authorization: Bearer <token>`。
豁免清单：`/api/health` + `/api/auth/login|guest|me` + `OPTIONS`（CORS 预检不带
Authorization，交 CORS 层应答；中间件注册顺序=鉴权内层、CORS 最外层——2026-11-09 修复预检 401）。
`USERS_ENABLED=false` 退回
旧单机模式（主 token 或放行）；用户体系开启但 PG 不可用 → 无法验证会话，放行
（降级诚实：登录端点此时同样 503）。CORS 白名单 `API_CORS_ORIGINS`。

**会话隔离**：conversations.user_id 归属在服务端落库时打点（application/chat/history.persist_result）。
NULL = 机器/历史域（机器主 token 与人类 admin 可见）；普通用户仅见本人；
越权 get/delete/rename 一律 404（不泄漏存在性）。游客会话**不落库**，多轮上下文走
进程内缓存（TTL 1h、封顶 6 轮、重启即失——诚实内存态）。

### 3.2 统一响应与错误模型🆕

**全局错误体**（所有非 2xx 响应）：

```json
{"error_code": 4291, "message": "请求过于频繁，请稍后再试", "trace_id": "…", "detail": {"retry_after": 12}}
```

| error_code | HTTP | 含义 |
|---|---|---|
| 4001 | 400 | 参数校验失败（detail 含字段级错误） |
| 4011 | 401 | Bearer token 缺失/无效（含登录凭据错误） |
| 4031 | 403 | 角色不足/能力被禁（游客访问受限路径、游客开关已关闭、非管理员访问 /api/system 控制台域前缀） |
| 4041 | 404 | 资源不存在（会话/评测快照）——非法标识一律走这里，不区分「不存在/格式错」；**会话越权同走 404**（不泄漏存在性） |
| 4091 | 409 | 重复提交（`client_msg_id` 命中去重窗口）/ 资源冲突（控制台建号重名） |
| 4131 | 413 | 上传体积超限 |
| 4291 | 429 | 触发限流（响应带 `Retry-After` 秒） |
| 5001 | 500 | 未分类服务端错误 |
| 5031 | 503 | 数据源降级/不可用（body 注明哪个源） |
| 5032 | 500 | 判分模型异源校验失败（评测启动/跑批时） |

### 3.3 `/api/chat/stream` 请求 schema🆕

```json
{
  "conversation_id": "uuid | null（null=新建会话）",
  "message": "string, 1..4000 字",
  "web_enabled": false,               // 前端「联网搜索」开关；WEB_SEARCH_PROVIDERS 留空=按钮不出现，即使 true 也无联网工具可挂
  "thinking_enabled": false,
  "image_refs": ["img_…"],            // 可选；先经 /api/vision 换取引用，禁止 base64 直传聊天端点
  "provider": "deepseek | glm | null", // null=跟随用户偏好
  "client_msg_id": "uuid",             // 幂等键：60s 去重窗口内同键重复提交 → 4091
  "lang": "zh | en"                    // 可选，缺省 zh；界面语言→回答语言（P1 英文回答：en 时 system prompt 注入语言节+澄清/兜底话术英文）
}
```

- **幂等语义**：防重复提交，不做断线续传（流式续传列为 M4 后演进）；前端重试必须换新 `client_msg_id`
- `image_refs` 由 `/api/vision` 产出（服务端缓存图片描述，TTL 10 分钟），避免大 body 打爆 SSE 端点；
  worker 将命中的描述以 `【图片内容 n】` 段拼进问题文本注入模型（**不落库**——描述是易逝旁路，
  会话存原始问题）；过期/未知 ref 静默跳过，不让它拖垮整轮问答
- `lang` 只影响**回答正文语言**：来源标题/引文保持原文不译；done 事件结构不变（`schema_v` 不动）

### 3.4 SSE 流式事件协议（v2 增强）

每行 `data:` 前缀 JSON；**每事件携带单调递增 `seq`**🆕（服务端生成，前端用于排查乱序/重复）：

| type | 含义 | 出现时机 |
|---|---|---|
| `ping`🆕 | 心跳（每 15s，含 seq） | 任意事件间隙——防反向代理空闲断连（Nginx `proxy_read_timeout` 默认 60s，v1 的隐式坑，写进协议而非部署手册） |
| `status` | 阶段提示（检索中/分析中/补充检索/整理历史/生成中/向您确认） | 至少一条 |
| `token` | 正文增量 | 有正文时 |
| `thinking` | 思考过程增量（不落库） | 仅深度思考 |
| `reset` | **清空已流正文**（工具调用文本泄漏防护） | 仅命中泄漏时 |
| `done` | 收尾，携带全部结构化结果 + **`schema_v: 1`**🆕 | 正常结束 |
| `error` | 错误提示（含 error_code） | 出错时 |

**事件先后序契约**（写入契约测试）：`status* → thinking* → token* → done|error`；
`reset` 之后**必须**重新出现 `status` 再进入 `token*`；`ping` 可插入任意间隙、不计入业务序。

`done` 关键字段：`sources`、`web_sources`、`charts`、`tool_called` / `tool_name` /
`tool_calls`（**工具轨迹**，逐轮）/ `rounds` / `hit_cap` / `phase_times`（主路径与降级路径段名两套，不合并）、
`trace_id`、`elapsed_ms`、`schema_v`。

**澄清轮特征**：`tool_name=ask_clarification` 且三个来源字段全空；可靠判定是
`phase_times` 两段且第二段标签为「澄清提问」。

### 3.5 限流语义🆕

- **客户端身份（按桶分）**：游客 = **独立更严桶** `GUEST_RATE_LIMIT`（默认 10 次/60s，按会话 token）；
  普通用户/管理员 = 主桶按 user_id；机器主 token 同主桶；legacy 开发模式 = Bearer token / 客户端 IP
- 窗口：滑动窗口 30 次 / 60s，仅问答类端点（`/api/chat/stream`、`/api/ask`、`/api/vision`）
- 429 响应**必须带 `Retry-After` 头**，错误体 error_code=4291
- **被限流请求不计入在线评测**（它没有产生回答，计入只会污染行为指标）
- 进程内实现；只保护入站 HTTP——评测内部调用走函数层（§3.6），天然不在限流范围内
- 闲置客户端条目每 300s 批量清理一次（只丢最新命中已滑出窗口的条目，配额语义不变）

### 3.6 `/api/ask`、`/api/chat/stream` 与评测链路的关系🆕

- `/api/ask` **长期保留**：降级路径（Ollama 类无 FC 场景的对应物——此处指无工具直连）+ 评测 smoke 直连
- **评测（G2/G3/G4）统一走内部函数层**（直接调用 agent 编排函数，不经 HTTP）：
  不挤占限流配额、不受鉴权影响、延迟口径纯净；快照 `env.link="internal"` 记录链路标识
- 在线评测挂在 `/api/chat/stream` 收尾事件处（真实流量），离线评测走函数层——两者天然隔离

### 3.7 图表规格

`{id(内容寻址), kind(bar|kpi), title(口径/时间窗/限定条件必须写进标题), source(配色分组), format(ratio|int|float), max(分数类必填), items[]}`

数值三重收口：小数归一 / 布尔不当数字（防幽灵柱）/ 非有限数拦截。

## 4. 数据模型

### 4.1 Qdrant 集合（版本化🆕）

**集合命名带版本**：`bidqa_knowledge_v1`，配置项 `QDRANT_COLLECTION` 指向当前集合。
**重建策略**：切分/嵌入策略变更 → 建新集合 `…_v2` → 离线导入 → **原子切换配置/别名** → 删旧集合。
（禁止原地「清空重建」——重建期间问答服务不得处于半可用状态。）

**向量组成（三路 Named Vectors）**：`dense`（bge-m3 API，1024 维，COSINE）+ `sparse`（bge-m3 学习型稀疏）+
`sparse_bm25`（**jieba BM25 灾备通道**，ingest 双写）。常态检索=dense+sparse 混合；
嵌入 API 不可用/断网 → 仅用 `sparse_bm25` 纯本地检索（查询侧 jieba 本地编码，不依赖任何外部 API）。

**payload 字段 schema**（入库管道 F4 校验，必填项违规**拒收**并列清单，检索侧不容错；`ctx_summary` 为可选增强字段，留空不拒收）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `source_type` | enum: 法规/流程/FAQ/招标文件 | ✅ | 入库侧枚举校验 |
| `title` | str | ✅ | 来源标题 |
| `text` | str | ✅ | 块正文（不含 ctx_summary） |
| `ctx_summary` | str | ➖ | 🆕上下文增强前缀（**有值才参与编码**；无摘要时留空合法入库，F3 诚实降级，不以前缀拼入 embedding 输入） |
| `chapter` | str | ➖ | 章节路径（FAQ 类可空） |
| `ref` | str | ➖ | 条款号（法规类必填） |
| `page` | int | ➖ | PDF 页码（招标文件类必填） |
| `url` | str | ➖ | 来源链接 |
| `batch_id` | str | ✅ | 溯源批次（关联 F8 原始文件登记） |

**检索参数表**（四级数字集中于此，02 引用；`rrf_k` 按问题分类确定性注入，非运行时可调）：

| 参数 | 默认 | 阶段 |
|---|---|---|
| `prefetch_dense` / `prefetch_sparse` | 30 / 30 | 召回 |
| `rrf_k`（按问题分类） | keyword 30 / mixed 60 / concept 90；经 `query_hybrid(rrf_k=...)` 注入两路独立查询 + `database/rrf.py:fuse_rrf(Σ1/(k+rank))`（勘误：旧 `FusionQuery` 固定 k=2，分类从未生效；`bm25_fallback` 单路不融合，该值仅为诊断） | 融合 |
| `rerank_candidates` | 15（上限 30） | 精排 |
| `final_top_k` | 5 | 产出 |
| `crag_threshold` | 0.35（M1 用黄金集 P-R 曲线定值，记录进 `docs/核心算法.md`）；仅对精排 relevance_score 有效，`hits[0].score` 不可用时不触发改写 | 纠错 |
| `crag_max_retry` | 1 | 纠错 |

### 4.2 Neo4j 图谱（含唯一性约束🆕）

```
(:SubjectMatter {name, category})   ← 中心（name 归一后唯一）
(:Purchaser {name, region})
(:Supplier {name, region})          ← name 归一后唯一
(:Agency {name})
(:Location {name, level})
(:Project {project_no, name, amount, publish_date})   ← project_no 唯一

(:Project)-[:FOR]->(:SubjectMatter)
(:Purchaser)-[:PROCURED]->(:Project)
(:Supplier)-[:WON]->(:Project)
(:Agency)-[:AGENTED]->(:Project)
(:Project)-[:IN]->(:Location)
```

- **唯一性约束（建图脚本必须先建）**：`Project.project_no`、`SubjectMatter.name`、`Supplier.name`——
  否则 Batch 导入重跑必产生重复节点（参考方案的已知易错点，此处显式钉死）
- **实体归一**（F5）：默认走数据加工批量通道 `SUBJECT_BATCH_*`（`--normalize-channel chat` 可改主槽位）；
  **仅组织字段 winner/purchaser/agency**（标的物是「同类不同物」重灾区、地区规则清晰，二者保持恒等）；
  按字段独立分批（≤50 名 / ≤4000 字符，单批失败只降级该批并记入 stats）；单组 >8 个别名视为病态归类、整组降级复核；
  置信度达标后还需过**确定性闸门**——仅标点/公司后缀/括号别名/重复拼接差异可自动合并，分公司/校区/附属等附加限定词一律进复核；
  映射固定落盘 `data/processed/graph_alias_mapping_{batch}.json`，重建用 `--mapping-file` 复用（零模型调用）；
  置信度 **< 0.85 的合并候选不自动合并**，导出 CSV 人工复核
  （`data/processed/graph_merge_review_{batch}.csv`），复核结果回填 mapping JSON 后重跑
- 6 类查询模板：标的物频次 / 均价与金额分布 / 供应商分布 / 地区分布 / 采购人分布 / 时间趋势；
  慢查询走 `begin_transaction(timeout=30)`
- 金额/时间放 `:Project` 节点属性（README 旧提法 HAS_TRANSACTION 已废弃，以本节为准）

### 4.3 PostgreSQL

**`bidding_procurement`**（业务明细；查询白名单 = 下表全部列，D3 直接引用本表，不另行维护）：

| 字段 | 说明 | 字段 | 说明 |
|---|---|---|---|
| `project_no` | 项目编号（**UNIQUE(project_no, batch_id)**🆕） | `project_name` | 项目名称 |
| `project_category` | 项目分类 | `project_stage` | 项目阶段 |
| `purchaser` / `purchaser_contact` | 招标人/联系方式 | `agency` / `agency_contact` | 代理机构/联系方式 |
| `winner` / `winner_contact` | 中标人/联系方式 | `award_amount` | 中标金额(**元**；文本金额「66万」在 **ingest 层唯一入口** `normalize_amount()` 归一)🆕 |
| `content` | 招标内容 | `location` / `region` | 项目地点/地区 |
| `subject_matter` | 标的物 | `source_url` | 来源网址 |
| `publish_date` / `change_date` / `plan_date` / `award_date` | 发布/变更/计划/中标时间（**publish_date 建索引**🆕，时间范围查询依赖） | `batch_id` | 导入批次 |

- **判重语义🆕**：`UNIQUE(project_no, batch_id)` + ingest 层 upsert（ON CONFLICT UPDATE）——
  同一 Excel 重复导入同批次=更新；跨批次=并存，由查询侧按 batch 过滤
- **过滤语义🆕**：`filters` 键 = 白名单列名（另接受中文别名，映射表 `postgres.FILTER_ALIASES`：地区/省份/城市→`region`、
  标的物/品目→`subject_matter`、中标人/供应商→`winner`、采购人/招标人→`purchaser` 等）；
  `region` 为**包含匹配**（真实值粒度混有省/市，如 `安徽省合肥市` 与 `安徽`，按省过滤用 `安徽省` 亦能命中），
  其余列等值匹配；`subject_matter` 样例库全 NULL ⇒ 该维度**整张不出图**、只回「不可用」
- **`conversations`**：`id, title, messages JSONB（内部带 schema_v🆕）, provider, user_id（用户体系归属；NULL=机器/历史域🆕）, created_at, updated_at`
- **`feedback`**：`id, conversation_id, question, rating(up|down), sources JSONB, trace_id, created_at`
- **用户体系三表🆕**：`users`（username UNIQUE / scrypt 口令散列 / role admin|user / disabled）、
  `sessions`（opaque token PK / user_id NULLable / role / expires_at——游客会话 user_id=NULL 且无 users 行）、
  `app_settings`（运行时键值，如 `guest_enabled`）；首次 `build_users_store` 空表自动种子管理员
  （`ADMIN_USERNAME/ADMIN_PASSWORD`，缺省 admin/admin123 + doctor 告警）
- **建表 SQL 单一事实来源🆕**：`backend/src/bidqa/database/schema.sql`（不引 Alembic；
  客户端连接时按此文件幂等建表；M2 前补一版文本 ER 图进本文档附录）
- 两表由客户端连接时自动建表（开发友好，参考方案同款）

### 4.4 评测快照（JSON，`eval/results/`）

- 结构：`{kind, env(被测/判分**指纹**（端点+凭据+模型）·是否自评·**link=internal/http**), summary, cases[], failed_cases[]}`
- **命名规范🆕**：`{kind}_{YYYYMMDD}_{git短hash}_{判分模型}.json`（如 `agent_20261108_a1b2c3d4_glm5.json`）——评估页按文件名排序展示
- **保留策略🆕**：滚动保留最近 100 个文件（页面展示条数仍为 20）
- **不落参考答案、不落回答正文**（历史教训保留为默认行为）；`null`=没测出来 ≠ `0`=得零分

## 5. 配置体系（`.env`）

**核心三列表🆕**（新增配置项必须同步登记此表）：

| 配置项 | 所属模块 | 必填性 | 缺失/异常时的行为 |
|---|---|---|---|
| `CHAT_BASE_URL` / `CHAT_API_KEY` / `CHAT_MODEL` | clients | **核心** | **启动失败**（无主模型无法服务）；通用 OpenAI-compatible 自填，无预置厂商枚举 |
| `CHAT_THINKING_MODEL`（可选） | clients | 能力型 | 留空=深度思考回退提示词注入 |
| `CHAT_PROFILES` + `CHAT_<name>_*`（可选） | clients | 能力型 | 主槽位多组命名 profile 供前端运行时切换；未配置=单激活配置、隐藏切换器 |
| `CHAT_MAX_TOKENS`（可选） | clients | 能力型 | 主槽位输出预算（chat/chat_tools/chat_stream 三路径注入，`chat_raw` 评测透传除外）；留空=不传（上游默认）。思考型上游先烧 reasoning 再出正文，预算不足时正文为空（finish=length），建议 8192 |
| `VISION_BASE_URL` / `VISION_API_KEY` / `VISION_MODEL` | clients | 能力型 | 图片解析功能降级（上传提示不可用） |
| `OCR_BASE_URL` / `OCR_API_KEY` / `OCR_MODEL` | clients | 能力型 | v2.3 双通道：文档/表格类图片按高分辨率原件 OCR 提取；缺失=自动路由退化为 Qwen 通用描述，手动「按文档解析」5031；health capabilities.vision_ocr 如实显示 |
| `JUDGE_BASE_URL` / `JUDGE_API_KEY` / `JUDGE_MODEL` | eval | 能力型 | 评测不可用；**配置后 G2 执行前指纹异源校验（端点+凭据+模型），完全相同拒绝跑批（5032）、仅同端点告警** |
| `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` / `EMBEDDING_MODEL`(SF) | clients | 能力型 | 启动成功；**降级=本地 jieba BM25 灾备通道**（sparse_bm25），health 显示降级 |
| `RERANK_*` | clients | 能力型 | 启动成功；跳过精排直取 RRF 融合结果（候选数=final_top_k） |
| `QDRANT_URL` / `QDRANT_API_KEY` | database | **核心** | **启动失败**（默认指向本地绿色服务 http://localhost:6333） |
| `NEO4J_*` | database | 能力型 | 图谱工具降级；health 显示未就绪 |
| `POSTGRES_*` | database | 能力型 | 业务库工具与会话存储降级 |
| `WEB_SEARCH_PROVIDERS` / `TAVILY_API_KEY` / `EXA_API_KEY` | tools | 能力型 | 名册留空=联网关闭（**前端不显示联网按钮**）；列名供应商须对应 key 已配才生效（缺 key 跳过，配置序=合并序）；配置 `RERANK_*` 后联网结果按检索 query 相关性重排（归一 [0,1]，缺失/失败=引擎原序+score 空） |
| `MINERU_API_KEY` | ingest | 能力型 | PDF 走 pdfplumber 本地兜底 |
| `SUBJECT_BATCH_API_KEY` / `SUBJECT_BATCH_BASE_URL` / `SUBJECT_BATCH_MODEL` | ingest | 能力型 | 数据加工批量通道：subject-batch run 与 `ingest graph --normalize`（默认通道）不可用（subject-batch build/fetch、graph 恒等建图不受影响）；同步并发编排（非平台 Batch API），可用 `--normalize-channel chat` 改走主槽位 |
| `API_AUTH_TOKEN` | api | 能力型 | **机器主 token**（脚本/e2e 免登录，语义=管理员级）；用户体系关闭时=旧单机鉴权；未配置且体系关闭=放行 |
| `USERS_ENABLED` | api | 能力型 | 默认 **true**（本机也启用登录）；false=退回纯 token 单机模式（旧测试/脚本兼容开关） |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | api | 能力型 | 首次启动 users 空表时的种子管理员（缺省 admin/admin123，**doctor 告警提醒改密**）；仅种子用，运行时读 users 表 |
| `SESSION_TTL_HOURS` | api | 能力型 | 登录会话有效期（默认 72h；opaque token 存 sessions 表，可吊销） |
| `GUEST_RATE_LIMIT` | api | 能力型 | 游客独立限流配额（默认 10 次/60s，独立桶；普通用户 30/60s 不变） |
| `ONLINE_EVAL_*` | eval | 能力型 | 默认关且**采样率默认 0**（行为指标全量免费）；点踩触发忠实度单维必评 |

- 优先级：真实环境变量 > 配置文件 > 内置默认值；`load_dotenv(override=False)`
- **降级规则🆕**：能力降级类配置缺失 = 启动成功 + health 显示降级；核心类缺失 = 启动失败
- **上游 429 重试🆕**：仅对 `token.sensenova.cn`（含子域）的 429 自动退避重试——流式与非流式一致，
  最多 4 次、尊重 `Retry-After`（缺失则 2/4/8s、单次≤30s、总等待≤45s）；**重试只发生在首字节之前**，
  不会重复输出；其他端点的 429 立即报错（5031 降级），不盲目重试

## 6. 进程模型

- 单进程启动；进程内状态（限流/在线评测/日志缓冲/追踪/压缩缓存）**假定单进程**，模块头必须写明
- `--reload` 会使进程内统计归零——页面标注「本次进程内」，不是 bug
- **workers=1 是硬性约定🆕**：`start.sh` 写死 `--workers 1`；config 启动时检测 worker 数>1 即告警退出（防呆）
- **优雅停机🆕**：`stop.sh` → SIGTERM → ①停止接收新请求 → ②进行中 SSE 连接发送 `error` 事件（code=5031「服务重启中」）后关闭（前端 A8 已有中断保留逻辑，两侧对齐）→ ③ToolRunner 取消未完成 futures（等待上限 30s）→ ④关闭连接池。H3 的 status 脚本须能发现「停止失败」的残留进程
- 多进程部署列为 M4 后的可选演进，不在本期范围
